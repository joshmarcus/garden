# designer review of context-garden/phase-04

**Persona:** designer · **Score:** 7/10 · 2026-09-05T22:40:15+00:00

Phase 04 raised the product's coherence in the places it set out to: one vocabulary for continue/unpause/resume, help panels, controls that apply on change with a saved mark, stale badges gone, rebase runs and the merge queue rendered, pages that never 500, and a Costs page whose numbers match the CLI. The late-landing features drifted from that standard: the operating-profile control is named three ways across rail, Config and CLI, a task id sits in a panel label and in help text, three new commands fall outside the help groups, the Kickoff panel leads every open phase page whether or not it applies, an approve card offers a primary button it knows will refuse, and the walkthrough that persona reviews depend on does not capture the phase's own new pages. Each is a small fix; together they are the difference between one product and a set of well-made parts.

## High

- **operating profile** — The rail, Config page, CLI and status line use 'operating profile', 'stop' and 'profile' for the same control, and 'profile' also names the separate observe feed level.
  - suggestion: Pick one word for the operating point and rename the observe level to 'feed' or 'observe level' on every surface and in docs.
- **phase page** — The Kickoff panel with a primary 'Kick off' button is the first thing on every open phase page, above the verdict, progress and task table, even on a phase well underway.
  - suggestion: Show it above the fold only while the phase has no approved tasks; afterwards fold it into a header note or move it below the task table.

## Medium

- **inbox approve card** — A draft with brief gaps shows 'Fix the brief before approving' beside an enabled primary 'Approve into…' button whose press only produces a refusal flash.
  - suggestion: Disable or demote the approve button while gaps exist and make fixing the brief (link to Suggest a change) the primary action.
- **config page** — tick_interval is listed both under live re-read values and under 'Needs a restart', and the operating-profile panel's eyebrow reads 'CG-221' (the CLI help also cites the task id).
  - suggestion: Remove restart-only keys from the live list, replace the eyebrow with a plain label like the other panels, and drop task ids from help text.
- **cli help** — move, retro-decide and canary appear in an unlabeled Commands box above the named help groups CG-156 introduced.
  - suggestion: Assign each a panel and add a test asserting every command names one.
- **task page** — A draft task page shows both 'Approve into [phase]' and a separate move 'phase' pulldown listing the same phases with different submit behaviour, and the Inbox shows the approve pulldown even with a single option.
  - suggestion: Hide the move pulldown on drafts and hide either select when it has one option, matching the task page's existing rule.
- **inbox questions** — Kickoff and retro question cards sit in the 'Needs a decision' group whose description says the loop stopped on a stall, cap, closed PR or failed worker.
  - suggestion: Give questions their own group or fold them into the worker-question group with a source label.
- **walkthrough** — garden walkthrough still captures the phase-02 page set; Costs, the backlog view and the retro page are never captured for persona review.
  - suggestion: Add the three pages to pages_for with a purpose line and a 'what to look at' line each.
- **docs** — The scaffolded garden-operate skill says any config change needs a restart, and docs/design.md lists automatic merging as a non-goal, both contradicting the shipped product.
  - suggestion: Update the skill template's config line and the design non-goals in one small PR.

## Low

- **inbox question card** — The worker's question is printed twice on its card because the reason line and the question line carry the same text.
  - suggestion: Use the reason line for context and show the question once.
- **costs** — Resume, trial, compare and edit runs fold into an unnamed 'other' activity that can be a large share on a small garden.
  - suggestion: Name common modes such as resume, or list the folded modes in the bar's hover title.
- **rail** — Spend appears three ways in the rail (a whole-dollar Runs figure, a Costs link, an hourly rate) and the rounded figure disagrees with the Inbox KPI; the profile select's default reads 'plain garden.yaml values'.
  - suggestion: Drop the dollar figure from the Runs link now that Costs exists and give the default option a plain name such as 'no profile'.
- **costs filter** — The Costs form submits every select on change yet keeps a visible Filter button, unlike the noscript fallback the rail uses.
  - suggestion: Use the same noscript pattern for the fallback button.
- **vocabulary** — A cancelled task's only action is 'Continue the loop', the TUI label is 'Continue loop', and the phase page names a 'planner-tier' review no surface defines.
  - suggestion: Label the cancelled-task action 'Reopen', align the TUI label, and name the tier the kickoff actually uses.
