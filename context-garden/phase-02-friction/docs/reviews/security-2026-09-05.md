# security review of context-garden/phase-02-friction

**Persona:** security · **Score:** 5/10 · 2026-09-05T02:48:52+00:00

Phase 02 added genuine, incident-driven defences: the GARDEN_ROOT sentinel and root-discovery refusal, checkouts outside the garden, a runner-side write fence with revert, a marker for the garden's own comments, bot-notice filtering, atomic writes, and signalled checks never read as a pass. But the loop still treats anything that arrives from GitHub or from a worker as trusted once inside: any PR commenter can author a worker's prompt, the worker runs with the operator's full credentials and unrestricted Bash and can push to main, PR text is rendered as raw HTML in a CSRF-free control panel, the fence exempts .garden/ and task files so scheduler state including the self-upgrade url can be rewritten, checks run branch code unfenced and execute retry commands from check output, and automerge plus auto-upgrade can carry an injected change all the way to a pip install on the operator's machine. Tests and lint are green; the gaps are design, not bugs, and the top three fixes (author trust on feedback, a scrubbed worker environment plus branch protection, HTML sanitization plus an Origin check) are small.

## High

- **feedback ingestion** — Any GitHub account that can comment on a PR gets its text placed verbatim into a revise brief for a shell-capable worker, with no author trust check.
  - suggestion: In feedback_since keep only comments with author_association OWNER/MEMBER/COLLABORATOR or a github.trusted_logins allowlist; park other comments on a needs-human card; wrap feedback in a fenced block labelled as data, not instructions.
- **worker credentials** — LocalRunner copies the operator's full environment (GH_TOKEN, SSH_AUTH_SOCK, API keys, gh config) into a worker with unrestricted Bash, and nothing prevents the worker pushing to main or using gh directly.
  - suggestion: Strip credential variables and point the worker at an empty gh/git credential profile; have garden doctor check branch protection on the product base branch; prefer a scoped deploy key for worker pushes.
- **web UI** — PR comments, worker output and review text are rendered with |md|safe through python-markdown, which passes raw HTML, giving stored XSS on a local control panel whose POST routes have no CSRF or Origin check.
  - suggestion: Sanitize rendered markdown with nh3 (or escape HTML before markdown) and reject POSTs whose Sec-Fetch-Site header is not same-origin or none.

## Medium

- **worktree fence** — The fence exempts .garden/ and every tasks/ path and reverts only transcript-named paths, so a worker can rewrite scheduler state (including _control.upgrade url/sha, budgets, another task's pending_feedback) and task files unnoticed; garden upgrade then pip-installs from the url stored in state.
  - suggestion: Fail the run on any worker-attributed write under .garden/ or a task file; make the sandbox the default once verified; re-derive the upgrade url from config and refuse a sha not reachable from origin/<base> of the tool clone.
- **checks** — Pre-PR and CI checks run the branch's code on the scheduler host with the full environment, resolve relative check scripts inside the worker's worktree, and execute a retry_command taken from a check's JSON output with shell=True.
  - suggestion: Run checks with the same scrubbed env (or sandbox) as workers, resolve check scripts against the garden root, and honour retry_command only from config.
- **automerge and upgrade** — Automerge requires only an LLM approve verdict (never a human approval) and does not pin the reviewed head sha; combined with upgrade: auto, an injected change can reach main and be pip-installed into the running scheduler with no person involved.
  - suggestion: Default automerge to requiring review_decision == APPROVED, record head_sha in last_review and hold when it moves, and make auto-upgrade skip shas whose PR had no human approval.
- **discovered work** — Worker-filed discoveries marked blocking are created ready and auto-dispatched by default with a worker-written body and reading list that can name any file under the garden root, including garden.local.yaml and .garden/state.json, for inlining into the next brief.
  - suggestion: Default discovered.auto_approve_blocking to false and restrict reading entries to docs/, specs/ and product paths, rejecting .garden/, garden*.yaml and dotfiles.

## Low

- **ssh runner and hooks** — SSH workers get no deny rules, task id and setup env keys are interpolated unquoted into the remote script, GARDEN_MESSAGE carries worker text into notify hooks, and redirects follow the Referer header.
  - suggestion: shlex-quote every interpolated value in REMOTE_SCRIPT and pass fence paths for SSH; document quoting for notify hooks; redirect only to same-origin paths.
