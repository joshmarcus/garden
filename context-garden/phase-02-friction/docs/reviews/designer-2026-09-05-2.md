# designer review of context-garden/phase-02-friction

**Persona:** designer · **Score:** 6/10 · 2026-09-05T03:01:42+00:00

The phase shipped strong individual pieces (attention cards with per-button explanations, the decision/notice Inbox split, per-run transcript pages, flash errors, the Herbarium) but did not reconcile the surfaces: the end-of-phase Inbox shows 14 'decisions' that are all already-deferred drafts with no way to clear them, a manual task sits under 'Auto-retrying', the same phase reports 127/104/112/108/131 tasks depending on the page, done tasks carry 'needs you' badges on the Board, one retry action has five names across web, TUI and CLI, and two different things are called Timeline. It feels like several good features rather than one product.

## High

- **Inbox** — All 14 counted 'decisions' are drafts already marked 'deferred by the feature freeze', and the only buttons are Approve and Drop, so the badge stays at 14 forever.
  - suggestion: Add a Defer action (records the note, moves the draft to a notice group or a next-phase bucket) so the badge counts only undecided items.
- **Counts** — The rail says 127 tasks, the phase page 104 in scope / 84 merged / 'hide 112 done', the Board 108 done, the Trellis 'hide done (131)'; the hide labels count 23 cancelled tasks as done.
  - suggestion: Compute phase figures once (store/graph) and have every surface read them; label hidden rows 'done or cancelled' and show cancelled separately.

## Medium

- **Board** — Done tasks (CG-012, CG-027, CG-083, CG-109) show a red 'needs you' badge because board_data reads needs_human without checking terminal status while the Inbox gates it.
  - suggestion: Clear needs_human on terminal transitions and skip the badge for terminal tasks, matching inbox.py.
- **Vocabulary** — Retry is 'Continue the loop', 'Retry', 'Reset→ready', 'e continue' and `garden retry`; drop is 'Drop' vs 'Cancel'; TUI `a` approves a task but accepts a decision.
  - suggestion: Write a one-page action vocabulary in docs/design.md (one verb per action) and make web, TUI footer and CLI use it.
- **Timeline naming** — The nav 'Timeline' opens /events (CLI `garden events`) while the task page has a separate 'Timeline' panel that duplicates the 'Log' panel below it.
  - suggestion: Name the page Events to match URL and CLI (or rename both), and merge the task page's Timeline and Log into one history.
- **Inbox retrying** — Manual task CG-029 (ready) is shown under 'Auto-retrying · A previous attempt failed; a new run is queued or in progress' though nothing will run.
  - suggestion: Exclude manual-runner tasks from the retrying rule and give them a card that says it waits for `garden take`.
- **Timeline digest** — 'Needed you' lists each worker question twice, repeats 'this PR is yours' up to five times per task, and dumps a seven-line git push hint inline.
  - suggestion: Dedupe by task and reason, collapse repeats to a count, and cut error text to one line with a link to the run.

## Low

- **Trials empty state** — The copy says to 'name two or more contenders, e.g. claude:sonnet' but the form is now pickers with '+ Add contender', and the button only appears on ready/draft/failed tasks without a PR.
  - suggestion: Rewrite the empty state to describe the picker and the states in which the button appears.
- **Priority** — The Board prints 'p1' while the phase table and task page print 'next · 1' and the CLI takes a bare number.
  - suggestion: Use the word scale on the Board too (or 'next · 1' in the tooltip and 'next' in the card).
- **Board views** — Columns and list order the statuses differently, and the list opens with seven empty group headings.
  - suggestion: Pick one order for both views and collapse empty groups into a single 'nothing waiting' line.
- **Task page** — A done task still offers Reset revision counter, tier/priority pulldowns and Suggest, and reads '1 revision(s)' while showing five revise runs after two manual resets.
  - suggestion: Hide mutating controls on terminal tasks (CG-142) and show 'N revise runs · counter reset K times'.
- **Log notes** — Triage notes are cut at 100 to 120 characters mid-word with no ellipsis at write time, so the full text is lost.
  - suggestion: Store the full note in the task log and truncate with an ellipsis only in cards.
- **Config and Herbarium** — Config shows 'Dispatch' twice, '$2000.0' vs the phase page's '$2000.00', and 'Dispatch is running' beside a footer saying 'scheduler loop on'; the Herbarium empty state offers only a CLI command.
  - suggestion: One eyebrow per section, a shared money format, one word for the loop, and a 'Close phase' button on the phase page.
