# designer review of context-garden/phase-02-friction

**Persona:** designer · **Score:** 6/10 · 2026-09-05T02:46:47+00:00

The phase delivered its goals (live output, notifications, friction harvesting, structured stop cards, flat brief cost) and every feature has a test, but the product reads as several good features rather than one coherent tool: the same retry action carries four names across web, TUI, CLI and README; three different things are called a decision; the budget card, Config page copy, design docs and README still describe the product as it was before this phase's own changes (no live budgets, no automerge, a garden.yaml that no longer exists here); and the in_review task page, the flagship state of the loop, has no primary action while the Inbox card does. Each fix is small; together they are the difference between a tool the single operator trusts at a glance and one they have to re-learn per surface.

## High

- **naming** — The same POST /tasks/{id}/retry is offered as 'Retry' and 'Continue the loop' on one failed task page, 'Reset→ready' in the TUI, 'e continue' in the README and 'garden retry' in the CLI.
  - suggestion: Pick one label (e.g. 'Retry') and use it on the card, toolbar, TUI binding, README and CLI help; hide the toolbar button when the attention card already offers it.
- **inbox vocabulary** — 'Decision' names three different things: the accept/reject worker-call group, the 'Needs a decision' attention group, and discovery duplicate/cancel cards filed under attention with their own Accept/Reject and a separate garden decide verb.
  - suggestion: Rename the attention group 'The loop stopped', move discovery cards into the accept/reject group, and make garden decide the single CLI verb for any Accept/Reject card.

## Medium

- **budget card** — The Inbox budget card and TUI still tell the person to edit garden.yaml, and the Config page says only pause and max_parallel are live, although CG-048 made budgets editable live from the phase page and garden budget.
  - suggestion: Put the phase page's amount + 'no budget' form on the Inbox card, make the TUI hint 'garden budget', and update the Config page intro and budgets section to say they are live.
- **task page hierarchy** — An in_review task page has no primary action or status panel; the PR is a small header link and the visible toolbar leads with Automated review, Persona review and Mark done, which does not merge.
  - suggestion: Add an in_review panel like the waiting_human and awaiting_triage ones with 'Review on GitHub' first, and relabel or explain 'Mark done' as recording a merge made outside the garden.
- **docs vs product** — design.md and roadmap.md list automatic merging as a non-goal while README documents github.automerge; design.md and architecture.md point at context-garden/phase-01-bootstrap/specs which CG-063 removed; notify.command is documented nowhere in the tool repo and garden init writes no notify key.
  - suggestion: Update the non-goals to 'automatic merging is opt-in and gated', fix the spec pointers to joshmarcus/garden, and add a notify block to README's garden.yaml section and to the init scaffold.
- **CLI surface** — garden --help is 64 flat commands with confusable neighbours (set vs set-status; budget, priority, difficulty, pause, set as five verbs for live settings) and the README command table and TUI key list predate most of this phase.
  - suggestion: Group commands into help panels (read, decide, run, configure, retro) and regenerate the README table and TUI key list from the current bindings.
- **resume** — 'resume' means unpause dispatch (garden resume), clear a task's stop (garden resume TASK), accept a no_change round ('Accept (resume)') and answer a question ('Answer and resume').
  - suggestion: Use garden unpause for the scheduler, keep resume for tasks, and change the accept button to 'Accept, continue the round'.

## Low

- **decision card** — 'The worker's full message' shows the raw GARDEN_RESULT JSON line to the person.
  - suggestion: Strip the GARDEN_RESULT line from the final message before rendering; the reason is already quoted above it.
- **friction form** — The Inbox friction form's product and phase selects are independent; a mismatched pair returns a bare JSON 404 instead of a flash, the one action route CG-122 missed.
  - suggestion: Post one product/phase value from a single select and flash the error on mismatch.
- **small inconsistencies** — The question card prints the question twice; priority renders as 'next · 1', 'p1' and '1' on different surfaces; garden status truncates headers to two letters at 80 columns and lacks a wont_do column; the Trellis legend omits wont_do and blocked; TUI a/x and c/w are two accept/reject pairs; doctor ends with 'see above'.
  - suggestion: Drop the duplicate question line, use priority_label everywhere, give status short headers that survive 80 columns plus a wont_do column, add wont_do and blocked to the legend, unify TUI accept/reject keys, and have doctor name the failing checks in its last line.
