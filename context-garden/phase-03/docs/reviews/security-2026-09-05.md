# security review of context-garden/phase-03

**Persona:** security · **Score:** 5/10 · 2026-09-05T10:21:05+00:00

The phase closed the four edges it named with solid code: an allowlist HTML sanitiser, an author-trust gate at the client layer, a shared environment allowlist for local, ssh and command checks, and an origin check on POSTs. But the isolation claims exceed the mechanism. Workers and branch-run checks still execute as the operator's user with HOME, so the gh token on disk is reachable (verified), the live garden's state.json and garden.yaml are writable and the fence ignores .garden/, and a check's JSON output can inject a shell command that runs in the scheduler's full environment. With automerge on, these chain into a self-approved merge. The origin check is bypassed by DNS rebinding (verified). The fixes are small and mostly local: a separate uid or sandbox for workers, hash checks on config and state across a run, never taking retry_command from check output, and a loopback Host requirement.

## High

- **worker isolation** — The scrubbed environment passes HOME, so a worker or pre-PR check reaches the operator's gh token and other on-disk credentials; gh auth token resolves with an empty environment.
  - suggestion: Run workers and command checks under a separate uid or container; meanwhile enable the harness sandbox by default and reword the docs to say only environment variables are scrubbed.
- **fence** — A worker's Bash or a branch's test suite can write .garden/state.json and garden.yaml on the live garden; the fence ignores .garden/ and only reverts tracked paths named in a transcript, so a forged approve verdict merges under automerge.
  - suggestion: Snapshot hashes of garden*.yaml and .garden/state.json at dispatch and before checks, and fail the run if they changed.
- **checks.ci** — poll.py runs a flaky check's retry_command with shell=True and the scheduler's full environment, and that field is taken verbatim from the check's JSON stdout, which a branch-controlled CI script produces.
  - suggestion: Take retry_command only from the config spec, never from check output, and run it in the scrubbed environment.

## Medium

- **web origin check** — Origin is compared with Host, so a DNS-rebound page whose name appears in both headers passes the check and can press every button.
  - suggestion: Require Host to be loopback/localhost or the bound address, or add a per-session CSRF token.
- **automerge** — An easy or medium tier PR against the self or tool product merges on the LLM review alone, and such a PR can change garden.yaml, task files and workflows that later run shell in the scheduler.
  - suggestion: Set automerge: false for self and provides_tool products, or hold automerge when the diff touches garden*.yaml, **/tasks/, .github/ or principles/.
- **trusted authors** — Every [bot] login is trusted, so a workflow or app that relays untrusted comment text can steer a worker.
  - suggestion: Trust only bots named in github.trusted_authors, or exclude github-actions[bot] by default.

## Low

- **notify.command** — GARDEN_MESSAGE carries worker-written text and the documented Slack example splices it unquoted into JSON.
  - suggestion: Build the payload with jq -n --arg in the example and note the variable is untrusted.
- **walkthrough** — Captured pages including run stderr, briefs and absolute paths are committed to the garden repo and pushed.
  - suggestion: Keep the garden repo private or drop stderr and command lines from the capture.
