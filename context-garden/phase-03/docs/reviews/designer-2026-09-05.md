# designer review of context-garden/phase-03

**Persona:** designer · **Score:** 5/10 · 2026-09-05T10:18:57+00:00

The loop's mechanisms improved a great deal and the deliberately written copy (frozen banner, terminal-task refusals, the Inbox decision/notice split) is coherent across CLI and web. But nearly every new state this phase introduced reached the UI unlabelled: the new event kinds print blank on the timeline, a mechanical rebase wears a model run's template with a literal 'harness' placeholder, the merge queue has no surface at all, the rail shows a review running on a merged task, done tasks still wear 'needs you' on the Board, and the majority of Inbox cards end in a checklist fragment ('] Tests cover…') because the last-log helper reads acceptance criteria as log lines.

## High

- **Inbox** — Eight of thirteen Inbox draft cards end in a garbage fragment like '] Tests cover the CLI…' because _last_log_line treats the last acceptance-criterion checkbox as a log entry.
  - suggestion: In inbox.py _last_log_line, only match lines inside the task's log section or skip lines starting with '- [ ]'/'- [x]'.
- **Board / task page** — Merged tasks still show a red 'needs you' badge on the Board (CG-164, CG-142) and 'automerge: held: GitHub reports the PR unknown' on the task page (CG-125) from stale state entries.
  - suggestion: Gate needs_human and automerge_blocked rendering on a non-terminal status in _board.html and task.html, and clear the leftover keys for already-done tasks on the next tick.

## Medium

- **Timeline** — The event kinds added this phase (rebase, merge_head, feedback_ignored, retro_failed, rebased_stale_base, phase_frozen) have no formatter, so the task timeline shows 'rebase' with an empty description six times on CG-125.
  - suggestion: Add a one-line case per new kind to the timeline formatter in task.html, e.g. 'onto main · mechanical · diff unchanged, verdict kept'.
- **Run page / Runs** — A no-model mechanical rebase run is rendered as a model run: 'rebase · harness · 0 min · $0.00', 'This run recorded a single claude-json result…', '(no brief recorded)', and an empty model cell in every runs table.
  - suggestion: Detect a run with no harness/model and render a single line 'mechanical rebase onto <base>, no model, no cost' with the transcript, brief and stderr tabs hidden.
- **Merge queue** — The merge queue's head, in-flight and left-the-queue states from CG-141/CG-176 appear on no page; an operator cannot see which PR is head or why nothing merges.
  - suggestion: Show a merge-queue line in the Board's in-review column or the Inbox review group: the head PR, whether it waits on CI, and the last drop reason.
- **Rail / stats** — The rail says 'Running now: CG-176 review · 3 min' while the Board lists CG-176 as done and the Inbox shows '0 PRs open' beside '1/3 reviews running'.
  - suggestion: Stop an in-flight review when its PR merges, or label the rail entry 'review of a merged PR' so the contradiction is explained.
- **Phase page header** — The phase header line leads with 'fixed brief cost ~3,513 tokens (head + rules + digest + product + goals)' and appends the retro-waiting warning last, so trivia precedes the one state a person needs.
  - suggestion: Move fixed brief cost into the Spend panel next to the tier table and render 'retro: waiting for personas (n of m)' as a banner beside the frozen one.

## Low

- **Freeze vs close** — Close phase has a web button but freeze/unfreeze is CLI-only, with the banner telling a web user to type garden unfreeze.
  - suggestion: Either add freeze/unfreeze buttons beside Close phase or make both CLI-only with the same pointer.
- **Vocabulary** — The persona review is called 'Persona review…', 'Run persona review', 'Run personas', 'Persona review of the body of work' and 'waiting for personas' across the task page, phase page and header.
  - suggestion: Use 'persona review' as the noun everywhere, including the retro-pending line.
- **Board badges** — Discovered tasks carry a 'found' badge on the Board while every other surface says 'discovered by', and it glues to the title in text rendering.
  - suggestion: Rename the badge to 'discovered' or remove it and keep the tooltip.
- **Task page accounting** — The 'auto review: approve (2 rounds)' count on CG-125 includes a review run that was superseded before it finished.
  - suggestion: Exclude superseded review runs from review_rounds when CG-144 closes them.
