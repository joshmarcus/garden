The controller health endpoint later remained responsive; a bounded stack dump showed the event loop idle and the watcher waiting on a GitHub subprocess, not a deadlocked event loop. Memory pressure, high/max and OOM counters were zero. New dispatch was paused through the product, active runs preserved, and the owner's feedback stored through Scheduler.triage. Pages recovered without restart.

The observed CG253 supervisor adopted a growing population of exited git children. Its source waits for the primary command before reaping those adopted exits. Their disappearance after that worker ended establishes a lifecycle defect, but does not prove it caused all HTTP/WSL timeouts. CPU throttling had occurred earlier; no diagnostic stack was captured during the worst interval. Normal full GitHub CI did not exercise a long-lived supervisor with repeatedly exiting adopted grandchildren, and the earlier broad resource incidents did not distinguish PID accumulation from memory pressure.

Prevention task CG-430 owns prompt adopted-child reaping, exit-status/containment regressions and bounded diagnostic follow-up. Its counterfactual is to prevent accumulation throughout a long-lived worker, rather than clean it only at exit. Existing CG382 owns request/history scan profiling; CG393 owns validation-wait vs stale classification. Preserve their work and use observations to decide whether an additional request-capacity repair is needed. Stress/load experiments stay opt-in.
